# Intersection of Two Linked Lists

## 1. Problem
Даны два односвязных списка. Нужно найти узел, в котором они пересекаются (сливаются в один общий хвост). Если пересечения нет, вернуть `None`.

## 2. Approach
Я использовал изящный алгоритм с двумя указателями, которые «меняются списками» при достижении конца.

**Трудности и неудачные подходы:**
Моя первая мысль была пройти по первому списку и сохранить все адреса узлов в хэш-сет (set), а затем идти по второму списку и проверять, есть ли узел в сете. Это работало, но давало дополнительную пространственную сложность O(n), что не очень красиво, если нужно сделать решение эффективным. 
Затем я пытался вручную вычислять длину обоих списков, чтобы выровнять их стартовые позиции, но код получался слишком громоздким и запутанным с кучей условий if/else. 
Идеальным решением стал метод двух указателей: указатель pA идет по списку A, а дойдя до конца, переключается на голову списка B. То же самое делает pB (идет по B, а потом по A). В итоге оба указателя проходят расстояние, равное сумме длин обоих списков (lenA + lenB), и встречаются ровно в точке пересечения (или оба доходят до None, если пересечения нет).

## 3. Time & Space Complexity
- **Time Complexity: O(n + m)**, где n и m — длины первого и второго списков. В худшем случае указатели пройдут оба списка целиком.
- **Space Complexity: O(1)**, потому что мы используем только два указателя (pA и pB), не создавая никаких дополнительных коллекций.

## 4. Reflection / Improvement
- **Is there a more efficient approach?** 
  Этот подход с двумя указателями уже является оптимальным по времени O(n+m) и по памяти O(1). Улучшить его дальше невозможно.
