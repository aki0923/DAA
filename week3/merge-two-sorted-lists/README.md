# Merge Two Sorted Lists

## 1. Problem
У нас есть два отсортированных односвязных списка. Нужно объединить их в один общий отсортированный список, соединив узлы первых двух.

## 2. Approach
Я решил эту задачу с помощью итеративного подхода с использованием вспомогательного («фиктивного») узла dummy. 

**Как это работает на примере:**
Допустим, list1 = [1, 2, 4] и list2 = [1, 3, 4].
1. Создаем пустой узел dummy, на который указывает указатель current.
2. Сравниваем первые элементы: 1 из первого списка и 1 из второго. Они равны, поэтому берем элемент из list1, прицепляем его к current.next и сдвигаем list1 дальше.
3. Теперь сравниваем 2 (из list1) и 1 (из list2). Единица меньше, значит, прицепляем 1 из list2 и сдвигаем list2.
4. Повторяем этот процесс, пока один из списков не закончится.
5. В конце просто присоединяем оставшуюся часть большего списка к нашему результату, так как оба исходных списка уже были отсортированы.

## 3. Time Complexity
**Time Complexity: O(n + m)**
Где $n$ и $m$ — это количество элементов в первом и втором списках соответственно.

**Объяснение:** 
В худшем случае мы проходим по каждому элементу обоих списков ровно один раз. Цикл while крутится до тех пор, пока один из списков полностью не исчерпается.

## 4. Space Complexity
**Space Complexity: O(1)**

**Объяснение:** 
Мы не создаем новые узлы в памяти (кроме пары указателей). Мы просто меняем существующие связи (next) между узлами исходных списков, поэтому дополнительная память не расходуется.

## 5. Reflection / Improvement
- **Is there a more efficient approach?** 
  Это и так самый оптимальный итеративный подход по времени и памяти ($O(n+m)$ по времени и $O(1)$ по памяти). Также можно было бы решить через рекурсию, но рекурсивный подход тратит дополнительную память в стеке вызовов ($O(n+m)$ по памяти), поэтому итеративный вариант даже лучше.
